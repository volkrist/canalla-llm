# Canalla 1.2.7 — план единственного LIVE Qwen прогона

**Статус:** подготовка завершена, платный запуск **не выполнялся**.
**Разрешение владельца:** требуется отдельно.

## Цель

Доказать, что настоящая Qwen (а не scripted planner) самостоятельно проходит цикл:

```
RESEARCH → PLAN → BUILD → RUN → TEST → GUI → FIX → RETEST → VERIFY → COMPLETE
```

на одной пользовательской задаче, с реальными инструментами и реальными side effects.

## Сценарий (один запрос, без подсказок по ходу)

> «Создай на моём компьютере приложение TaskDesk для управления задачами: локальная база,
> создание, поиск, статусы, простой веб-интерфейс и тесты. Запусти его, проверь интерфейс,
> найди и исправь дефект, подтверди результат.»

Всё остальное — дело модели: она выбирает инструменты, план и порядок.

## Жёсткие пределы

| Параметр | Значение | Почему |
|---|---|---|
| GPU Pod | **не более 1**, один за раз | правило цикла |
| Тариф | ≤ $1.79/ч | существующий предел |
| Длительность Pod | **≤ 480 с** | $1.09/ч × 480 с = **$0.145** ≤ $0.15 |
| Watchdog | остановка инициируется на **430 с**, подтверждение до 480 с | 50 с запаса на stop |
| Бюджет прогона | **≤ $0.15** | разрешённый предел |
| Ожидание capacity | **не более 60 с**, без `--capacity-timeout 1200` | правило 1.2.6 |
| Повторный Pod | **запрещён** при FAIL | один прогон |

Остановка: сначала `compute stop` через Gateway, затем проверка `pods == []`, затем фиксация
фактического расхода по балансу.

## Критерии PASS (все обязательны)

1. `origin=model` у каждого шага — журнал `task_events` / `tool_runs` это подтверждает.
2. Файлы приложения созданы model-origin вызовами `write_file`/`patch_file`.
3. `pytest` реально запускался и **второй** прогон прошёл.
4. Приложение реально поднято (процесс жив, порт слушается, HTTP отвечает).
5. GUI реально управлялся (`browser_gui` или `window_*`), есть скриншоты.
6. Дефект воспроизведён до исправления и отсутствует после (тест до/после).
7. Задача `COMPLETED`, `verification.evidence_ok = true`.
8. Нет повторных side effects (`repeated_payloads: []`, `duplicate_tools: []`).
9. Pod остановлен, `pods []`, расход ≤ $0.15.
10. Пользовательские данные и `device_id` не изменились.

**FAIL** — если хотя бы один пункт не подтверждён фактом. Один FAIL = одна попытка, дальше
только бесплатный разбор.

## Что проверяется ДО Pod (бесплатно)

`artifacts/acceptance-127/live-qwen/preflight.py --check` (read-only):

- Gateway `/health` = ready, `pods []`;
- баланс RunPod читается, стартовое значение записано;
- установленная 1.2.6 жива, `/health` = 200, версия совпадает;
- device online, Computer Ready, Tor Ready;
- текущий расход цикла и потолок;
- свободное место на диске под TaskDesk;
- отсутствие второго runner/coordinator.

Любой пункт `BLOCKED` → Pod **не создаётся**.
