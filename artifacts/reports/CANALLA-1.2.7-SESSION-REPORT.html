1. Резюме

За сессию пройден путь от «есть только отчёт о прошлых платных попытках» до собранного, подписанного updater-ключом и полностью проверенного установщика 1.2.7, у которого снят единственный оставшийся внешний блокер — Authenticode.

Главные результаты:

  • Найдена и закрыта настоящая причина, почему реальный LIVE не считался PASS: модель выполнила работу, приложение работало, но независимая проверка (verify_result) не была вызвана, и ничто её не требовало. Контроллер теперь требует её сам; это доказано replay сохранённого трейса и тестами.
  • Собран установщик 1.2.7: updater-подпись production-ключом 9B328EFF111D1FB2, Authenticode отсутствует по решению владельца, SHA-256 зафиксирован.
  • Полный релизный гейт release-gate.py candidate — PASS: 22 шага, 0 FAIL, 0 BLOCKED.
  • Все бесплатные проверки зелёные на релизном дереве: backend 1184, gateway 262, frontend 328, Playwright 25, Rust 134, acceptance-матрицы 66/66 + 31/31 + 28/28 + 16/16.
  • Развёрнутый Gateway проверен вживую без Pod: dry-run PASS, окно поиска закрылось само.
  • Production 1.2.6 не изменена и перепроверена после всех работ.
  • Платных Pod не создавалось с момента закрытия серии; провайдер подтверждает 0 Pod.

Что не сделано и почему — честно перечислено в разделе 12: чистая VM для install/upgrade, Linux-хост для Ubuntu-части и отдельное разрешение на публикацию.

2. Что требовалось

2.1. Задание №1 — автономная работа до результата

Владелец передал большой автономный мандат: довести Canalla 1.2.7 до технически завершённого состояния, доказав на настоящей Qwen (не mock), что продукт способен самостоятельно выполнить сложную задачу. Ключевые требования:

  1. Начать с фактического аудита (git, планировщик, монитор, Pod, балансы), не верить отчёту.
  2. Не допускать скрытых расходов; сверять Pod, счётчики и баланс.
  3. Не создавать второй Pod, пока судьба предыдущего не установлена.
  4. Держать GPU-мониторинг каждые 30 секунд независимо от редактора.
  5. Быстрый захват GPU (fast path) без повторной подготовки.
  6. Проверить всю цепочку таймаутов SSE → backend → модель и покрыть её бесплатными тестами.
  7. Максимально использовать оплаченный Pod: сначала модель, инструменты, задача, проверка.
  8. Минимальное доказательство реальной модели: Pod → llama.cpp → GGUF → токены → MODEL_RESPONSE → tool call → исполнение → результат → следующий шаг.
  9. TaskDesk: FastAPI + SQLite + GUI + CRUD, созданный и проверенный моделью.
  10. Независимый verifier, а не доверие словам модели.
  11. Autonomous repair: модель сама исправляет реальную ошибку.
  12. Durable resume.
  13. Честная шкала автономности LEVEL 0–7.
  14. Watchdog, деньги, cleanup.
  15. Recovery-сценарии A–H.
  16. Невмешательство в production 1.2.6.
  17. Компьютер и Tor сохраняют обязательные свойства.
  18. Бесплатные проверки после каждого исправления, полный CI перед заявкой RC.
  19. Управление работой как state machine; отчёт только по существу.
  20. Итоговый отчёт по форме A–K.

Отдельным оверрайдом: бюджет $2.00, один Pod за раз, число попыток не ограничено, внутри бюджета разрешение на каждую следующую попытку не запрашивается.

3.2. Причина, по которой реальный прогон не был PASS

Прогон e1845955 создал и запустил TaskDesk, прошёл тесты, отдал HTTP 200, сохранил строку в SQLite, независимый браузер отрисовал страницу — и всё равно не был зачтён, потому что provenance остался INCOMPLETE_TRACE.

Вместо предположений был сделан replay сохранённого трейса через текущий классификатор:

Проверка replay Результат
Воспроизведение записанного вердиктаточно INCOMPLETE_TRACE, 18 живых ответов, 17 вызовов, 17 связанных результатов
Несвязанные исполнения модели0 (unmatched_model_executions: [])
Отсутствующее звеноодно — событие VERIFY_PASSED
Контрфактическая проверкас одним добавленным VERIFY_PASSED классификатор даёт REAL_MODEL_CONFIRMED

Вывод: дефект был не в модели и не в классификаторе, а в том, что завершение задачи не требовало независимой проверки. Это исправлено в коде (раздел 10, п. 1).

10. Дефекты, найденные и исправленные

10.1. Исправлено в этой сессии

  1. Завершение без независимой проверки. next_forced_action теперь требует ровно один verify_result после зелёных тестов; проверки строятся из записанных файлов и тестовой команды; новая запись снова делает проверку должной.
  2. Тесты запускались не из того каталога. Пакетная раскладка (taskdesk/app + taskdesk/tests) проверяется из taskdesk/, а не из корня, где editable-app перекрывает пакет проекта.
  3. Evidence не переживало %TEMP%. Снапшот проекта в evidence-каталог, полный provenance-events.jsonl, id в tool-execution.jsonl, self-test пишет в свой каталог.
  4. Type gate не соответствовал заявленному 0/0. Поставляемый код исправлен (0/0 на 153 файлах); тесты и скрипты вынесены из гейта решением о scope и измерены отдельно (358 диагностик) — это записано в docs/AI-HANDOFF.md.
  5. Ruff-дрейф. 12 файлов не соответствовали форматтеру; приведены в порядок.
  6. Sidecar устаревал после правок backend. Пересобран; штамп снова совпадает с деревом.
  7. Права env-файла Gateway. root:root 0600 → root:alex-gateway 0640; operator CLI снова выпускает коды активации.
  8. Self-test затирал evidence платного прогона. Теперь пишет в self-test/.

15. Правило на будущее

Владелец попросил всегда делать такой отчёт. Зафиксировано:

  • после каждой существенной сессии (или по явной просьбе) на Рабочий стол кладётся полный отчёт в двух форматах: .md (машиночитаемый) и .html (открывается в браузере);
  • отчёт содержит: что требовалось, что сделано, чем доказано, сколько стоило, что осталось, состояние production и git, индекс evidence;
  • в отчёте не заявляется PASS без доказательства; неизвестное остаётся неизвестным;
  • копия отчёта сохраняется в репозитории (artifacts/reports/) и коммитится.

Это правило оформлено как навык агента desktop-report, чтобы применяться и в следующих сессиях.
