A. Цель

Исправить причину самопроизвольного платного запуска, реализовать LEVEL 7 resume внутри существующего harness и не блокировать инженерную работу финансовым состоянием.

B. Причина инцидента (найдена в коде, не в догадке)

install_monitor.ps1 регистрирует задачу с <Repetition><Interval>PT1M</Interval>, StartWhenAvailable=true и RestartOnFailure PT1M. Пауза хранилась в state.json — том самом файле, который каждый проход монитора перезаписывает из памяти. Процесс, уже работавший в момент паузы, записал обратно monitoring_enabled: true, минутный триггер поднял новый экземпляр, и тот купил Pod для уже пройденного LEVEL 6.

Исправление (код):

  1. monitor.paused — отдельный файл паузы. Проверяется до всего в run_check и в automation_mode; не может быть перезаписан состоянием. Пишется --disable, удаляется --enable; переживает рестарт процесса, планировщика и перезагрузку.
  2. ARMED execution manifest (execution-manifest.json) — без него дочерний grant не создаётся вообще. Проверяются: state == ARMED, batch_id, scenario_id, scenario_hash (sha256 live_acceptance.py), code_commit == git HEAD, max_cost <= authorized_cost.
  3. Монитор больше не может купить Pod «потому что GPU видна и деньги есть».

D. Реализация --resume (код, не план)

В live_acceptance.py добавлены:

  • флаг --resume и --resume-after-tools;
  • _interrupt_and_resume(...): ждёт N реально завершённых ToolRun, пишет checkpoint (task_id, status, число digests, счётчик tool runs), завершает изолированный backend (terminate → wait(30) → kill), фиксирует exit_code и статус задачи после смерти, поднимает новый backend с той же БД, тем же data root, тем же workspace и портом, ждёт /health, затем вызывает штатный POST /tasks/{task_id}/resume и собирает SSE-поток;
  • resume-evidence.json с interruption/restart/resume;
  • resume_checks: checkpoint получен, процесс завершён, задача не была COMPLETED, backend поднят, тот же task_id, новый прогресс после рестарта; при невыполнении вердикт — RESUME_FAILED, а не PASS.

Используется именно существующая цепочка продукта POST /tasks/{key}/resume → LocalTaskController.resume → stream_response(action="resume"); вторая система оркестрации не создавалась.

E. Что ещё не сделано и почему LIVE не запускался

Обязательный fake-LLM E2E двумя процессами (раздел 6 задания) не выполнен: нужен локальный OpenAI-совместимый сервер, детерминированно выдающий tool calls до и после прерывания. Без него LEVEL7_FREE_E2E = NOT_RUN, а значит LIVE запрещён и собственным preflight, и заданием.

Платный запуск не выполнялся: 0 Pod создано, 0 денег потрачено в этой сессии.

F. Финансы и лимит

Исходное разрешение задавало денежный потолок $5.00, резерв $8.50 и «не более одного одновременного Pod». Лимит «3 Pod» — техническая настройка серии, а не денежное полномочие.
