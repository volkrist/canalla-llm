## 3. Первопричина последнего T4 LIVE (найдена бесплатно)

Последний платный T4-сеанс (L40S, `live-20261111T095726`) дал `assistant status=error` и **не создал
запись в `local_tasks`**. Это два независимых дефекта продукта, а не capacity.

### 3.1. Классификация: промпт T4 не был задачей

`LocalTaskController.open()` создаёт `local_tasks` только когда включён `autonomous`. Для промпта T4

> «В папке …\T4L открой t4l.txt, сохрани его содержимое в t4l_out.txt, затем открой t4l_out.txt и
> подтверди содержимое. В конце выведи T4L_DONE.»

ни один сигнал старой цепочки не срабатывал — проверено кодом, а не на глаз:

```
T3L  computer=True   -> задача создавалась
T4L  computer=False  -> open() возвращал None
```

`looks_like_computer` знал «прочитай файл», но не «открой `<file>`» / «сохрани … в `<file>`»;
`looks_like_autonomous` требовал «полностью / пока не / исправь…»; coding/security/git — нет.
Итог: Qwen получала инструменты (`computer_mode=ask`) и **работала без задачи** — без плана,
прогресса, дедлайна и без цели для Resume. Именно поэтому harness не нашёл task id и не записал
evidence.

### 3.2. Смерть хода: исчерпание пула БД, а не таймаут модели

В логе backend в 19:03:07:

```
sqlalchemy.exc.TimeoutError: QueuePool limit of size 5 overflow 10 reached, connection timed out,
timeout 30.00
  File "app\chat_stream.py", line 413, in generate
  File "app\tools\orchestrator.py", line 564, in prepare
  File "app\tools\executor.py", line 576, in execute      → policy.preferences(db, …)
```

Тот же `TimeoutError` одновременно уронил `queue_monitor` и `compute_monitor` и `current_user`
(то есть база была занята целиком, а не один запрос). Причина — не модель и не Gateway:

* `_device` (`require_device`) делал `row.last_seen = now(); db.commit()` на **каждый**
  аутентифицированный запрос устройства, то есть каждый heartbeat и каждый poll очереди заданий
  был записью;
* хост-цикл опрашивает очередь несколько раз в секунду; в логе видно всплеск ~20 одновременных
  `GET /tools/devices/jobs` + `POST /tools/devices/heartbeat` за 250 мс;
* 15 соединений пула оказались заняты ожиданием единственного писателя SQLite, а собственный
  запрос хода чата ждал соединение 30 с и падал **нетипизированным** `TimeoutError`
  (`generation_failed type=TimeoutError`, `stream_interrupted`).

Классификация и пул усиливали друг друга: без задачи не было учёта прогресса, а нетипизированный
таймаут не давал ни задачи, ни понятной причины пользователю.

## 8. Максимально возможная стоимость одного T4 LIVE

* Реальная ставка Gateway за L40S — **$1.09/ч** (каталог показывал $0.79), A100 — $1.79/ч.
* Жёсткий потолок Pod — 600 с; худший случай на L40S: 600 с × $1.09/3600 = **$0.1817**.
* Фактическая длительность прошлых сеансов: **486 с** (L40S, $0.1472) и **491 с** (A100, $0.2441);
  ожидаемая стоимость T4 LIVE на L40S — **$0.145–0.157**.
* В текущем лимите осталось **$0.1496** = **494 с** по ставке L40S — то есть попытка возможна
  только «под ноль», без запаса даже на одну минуту, и любой сдвиг старта её сорвёт.

**Вывод:** для безопасного одного T4 LIVE нужен лимит с запасом. Достаточно поднять потолок цикла
примерно до **$1.05–1.10** (то есть +$0.20–0.25), тогда худший случай 600 с ($0.18) покрывается
дважды. Никаких денег до окончания этой бесплатной диагностики не запрашивалось, и сейчас расходы
не требуются: всё, что можно было доказать бесплатно, доказано.

## 11. Что изменилось для будущих прогонов

* Платный сеанс больше не может «потерять задачу»: любой промпт с именованным файлом и действием
  создаёт `local_tasks`, а значит имеет план, прогресс, дедлайн и цель для Resume.
* Опрос устройства перестал быть потоком записей: всплеск из 20 запросов даёт максимум 4 записи
  вместо 20, и чат больше не конкурирует с ним за пул.
* Если база всё же занята, пользователь получает `database_busy` с понятным текстом, а не пустое
  «поток прерван», и задача остаётся возобновляемой.
* Финансовый контролёр ориентируется на баланс провайдера, а не на оптимистичную сумму строк.

## 12. Остаточные риски

* Один платный сеанс всё ещё может не уложиться в 480–520 с, если Qwen выберет длинные шаги; тогда
  Pod будет остановлен watchdog-ом, а evidence сохранён как BLOCKED, а не как PASS.
* Учёт провайдера может добавить поздние начисления; лимит с запасом это покрывает.
* T4 LIVE остаётся единственным обязательным непройденным гейтом, и публикация без него запрещена.
