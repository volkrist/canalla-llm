## 5. Проверка S3-копирования (официальный S3-compatible API)

Источник: `https://docs.runpod.io/storage/s3-api.md`, `https://docs.runpod.io/storage/network-volumes.md`
(12.10.2026).

| Вопрос | Ответ |
|---|---|
| Записать GGUF напрямую в новый Volume без CPU Pod | **ДА** — «manage files on your network volumes without launching a Pod». Нужны байты на доверенной машине (или S3-endpoint). |
| Какие ДЦ поддерживают S3 API | **15**: `EU-CZ-1, EU-RO-1, EUR-IS-1, EUR-NO-1, US-CA-2, US-GA-2, US-IL-1, US-KS-2, US-MD-1, US-MO-1, US-MO-2, US-NC-1, US-NC-2, US-NE-1, US-WA-1`. **`US-TX-3` (первичный том) в список НЕ входит** — байты первичного тома через S3 не прочитать. |
| Credentials | Отдельный **S3 API key** (access `user_***`, secret `rps_***`) из консоли `Credentials → S3 API Keys`; в AWS CLI `AWS Access Key ID` = **user ID**, `AWS Secret Access Key` = secret S3-ключа. Это **не** `RUNPOD_API_KEY`. |
| Ограничения по размеру файла | `PutObject` **< 500 MB**; больше — multipart (AWS CLI делает автоматически); max part 500 MB; **max объект 4 TB** (= max объём тома). `sync` ограниченно поддержан (>10 000 файлов / сложные структуры). |
| Расходы на передачу | **Не тарифицируется.** «Using the S3-compatible API does not affect pricing»; «no fees for data ingress or egress». Хранение — обычное **$0.07/GB-мес** (< 1 TB). |
| SHA256-проверка после копирования | S3-API отдаёт **MD5 ETag** (`HeadObject`/`GetObject`) — первичная проверка. **SHA256** вычисляется только чтением байтов с тома (`sha256sum` на Pod либо download+hash). Своё: SHA256 записать на источнике **до** копирования и сверить после. |
| Может ли Pod из `US-TX-3` писать в новый том | **ДА** — S3-endpoint принадлежит ДЦ тома, вызывается из любой точки; достаточно, чтобы **новый** том был в S3-совместимом ДЦ. |

**Экономичный путь копирования (один CPU Pod, без второго):** один CPU Pod в `US-TX-3` (первичный
том примонтирован) читает GGUF и пишет напрямую в новый том через S3-endpoint нового ДЦ:

```bash
apt-get update && apt-get install -y awscli
sha256sum /workspace/models/orcarouter-qwen38/*.gguf    # записать источник ДО копирования
aws s3 sync /workspace/models/ s3://NEW_VOLUME_ID/models/ \
  --region US-KS-2 --endpoint-url https://s3api-us-ks-2.runpod.io/ --cli-read-timeout 7200
aws s3 cp /workspace/start-llm.sh s3://NEW_VOLUME_ID/start-llm.sh \
  --region US-KS-2 --endpoint-url https://s3api-us-ks-2.runpod.io/
aws s3 cp /workspace/check-llm.sh s3://NEW_VOLUME_ID/check-llm.sh \
  --region US-KS-2 --endpoint-url https://s3api-us-ks-2.runpod.io/
```

SHA256 на источнике записать **до** копирования; после — сверить (MD5 ETag + выборочный SHA256).

**Путь без Pod вообще** возможен только если известны источник и SHA256 модельных байтов на
доверенной машине. В репозитории **источник `orcarouter/Qwen3.8-27B-Uncensored` и его SHA256 НЕ
зафиксированы** (`docs/architecture.md` — «model download … not implemented»), поэтому этот путь
сегодня нельзя обещать; при первом контакте источник надо найти и закрепить (URL + SHA256), тогда
копия станет без-Pod.

**Первичный том `uwgeaie5b0` не изменялся и не меняется.**

### B. После выбора ДЦ — конфигурация placement (НЕ применять без разрешения)

В env Gateway (аддитивно к существующему):

```
RUNPOD_DATACENTERS=US-TX-3:uwgeaie5b0,<NEW_DC>:<NEW_VOLUME_ID>
RUNPOD_REPLICAS={"replicas":[{"volume_id":"<NEW_VOLUME_ID>","datacenter":"<NEW_DC>","model_id":"<llm_model>","model_path":"/workspace/models/orcarouter-qwen38/orcarouter_Qwen3.8-27B-Uncensored-Q5_K_M.gguf","model_sha256":"<SHA256>","model_bytes":<BYTES>,"runtime_version":"<runpod_runtime_version>","bootstrap_version":"<gateway version>","last_verified":"<ISO8601Z>","ready":true}]}
```

`require_records` выводится автоматически: добавленный том обязан нести проверенную запись, иначе
placement отклоняется (`replica_not_ready`), а не отдаёт чужие веса. Всё остальное (один managed
Pod, durable `waiting_capacity`, автоматический выбор, user `max_hourly_price`, A10/A11, idle-stop,
отсутствие duplicate create) не изменяется — проверено в §«Готовность Canalla» отчёта ветки.

**Порядок:** подтвердить ДЦ → создать том → скопировать и проверить модель → включить placement →
короткий живой GPU-тест → приёмка → только тогда релиз 1.2.1.
