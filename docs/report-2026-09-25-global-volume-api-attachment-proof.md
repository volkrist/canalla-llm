# ИТОГ

**GLOBAL VOLUME PUBLIC API ATTACHMENT = NOT ATTEMPTED**

**Причина ровно одна и она проверяемая: реальный ID глобального тома нельзя прочитать ни через одну
публичную поверхность API.** Тома нет в списке хранилищ аккаунта, нет в биллинге, нет ни одного
Pod'а, монтирование которого могло бы его показать, в v2 нет ни одного пути для глобальных томов, а
v1 такого пути не имеет вовсе. Придумывать ID запрещено заданием («Do not guess it»), поэтому
единственный корректный шаг — **не отправлять запрос** и запросить ID у вас.

Это **не** `FAIL`: отказ провайдера не наблюдался, потому что отправлять было нечего. Выдумывать
`FAIL` я не буду.

Всё, что нужно для немедленного продолжения, уже готово: одна команда делает **ровно один**
ограниченный тест (CPU, без GPU, без повторов), проверяет запись/чтение и убирает за собой.

# §1. ПОЧЕМУ ID НЕЛЬЗЯ ПРОЧИТАТЬ (полная проверка, не «не нашёл»)

| Поверхность | Результат |
|---|---|
| `GET /v2/network-volumes` | **200, но возвращает только `uwgeaie5b0`** — глобального тома в списке нет |
| Параметры этого запроса | в живой схеме у него **нет ни одного объявленного query-параметра** (скрытого «include global» не существует) |
| `GET /v2/billing/network-volumes` | 200, `uniqueNetworkVolumeCount: 1` — только региональный том |
| `GET /v2/pods` | 200, Pod'ов **0** — значит нет и Pod'а из консоли, чей `mounts` показал бы ID |
| **Все 38 путей живого v2** | storage-пути только такие: `/v2/network-volumes`, `/v2/network-volumes/{id}`, `/v2/billing/network-volumes`. Пути для глобальных томов **нет** |
| Поиск по всему документу OpenAPI | `globalvolume` = 0, `global-volume` = 0, `storagevolume` = 0, `storage_volume` = 0 |
| `VolumeType` (enum) | `STANDARD`, `HIGH_PERFORMANCE` — значения `GLOBAL` нет |
| `GET https://rest.runpod.io/v1/network-volumes` | **400**: такого пути/метода в спецификации v1 нет |
| GraphQL | интроспекция запрещена сервером (`INTROSPECTION_DISABLED`), в документированной поверхности глобальных томов нет |

Вывод: **публичный API не только не умеет подключать глобальный том — он его даже не видит.** Именно
поэтому ID обязан прийти от вас из консоли. Это, кстати, и ответ на вопрос §1 задания «console/storage
pricing if available through account/provider data»: **через account/provider data — недоступно**.

# §2. ATTACHMENT PROBE — подготовлен точно, но не отправлен

Тест готов как одна команда (без GPU, без повторов, с уборкой):

```
python scripts/global-volume-attach-test.py --volume-id "<ID из консоли>" --live
# кросс-ДЦ проверка (только если первый тест принят):
python scripts/global-volume-attach-test.py --volume-id "<ID>" --live --cross-dc US-KS-2
```

**Точное тело запроса, которое будет отправлено ровно один раз** (это вывод `--dry-run`, ничего не
создано; ID подставлен-заглушка):

```json
{
 "name": "canalla-gv-dryrun",
 "cloud": "SECURE",
 "image": "alpine:3.20",
 "disk": 10,
 "cpu": {"id": "cpu3c", "vcpuCount": 2},
 "mounts": {"network": [{"volumeId": "GLOBAL-VOLUME-ID-FROM-CONSOLE", "path": "/workspace"}]},
 "args": {"entrypoint": ["/bin/sh", "-c"],
          "cmd": ["set -x; echo CANALLA_GV_START; ls -la /workspace || echo CANALLA_GV_NO_MOUNT; mount | grep -i workspace || echo CANALLA_GV_NOT_IN_MOUNTS; printf '%s' '<токен>' > /workspace/global-volume-canalla-test.txt || echo CANALLA_GV_WRITE_FAILED; cat /workspace/global-volume-canalla-test.txt; echo; echo CANALLA_GV_WRITE_OK; echo CANALLA_GV_DONE=<токен>; sleep 300"]},
 "dataCenterIds": ["US-TX-3"]
}
```

Почему именно так, по живому контракту:

* `mounts.network` — **единственное** поле в контракте, способное нести хранилище; третьего вида нет;
* CPU-конфигурация взята из живого каталога: `cpu3c` («Compute-Optimized»), `$0.03` за vCPU/час,
  2 vCPU → **≈$0.06/час**, то есть минуты теста стоят меньше цента. GPU не запрашивается вообще;
* `args` использует документированную объектную форму `{"entrypoint": [...], "cmd": [...]}`;
* токен в файле содержит ID тома и UTC-время, чтобы старая запись никогда не была принята за новую.

**Ожидаемая стоимость:** первый тест <$0.01, кросс-ДЦ тест <$0.01 (Pod живёт минуты и сразу
завершается). Сейчас потрачено **$0**.

# §3. ЕСЛИ API ОТКЛОНИТ

Скрипт записывает и печатает ровно то, что требует задание: **HTTP статус**, **код провайдера**,
**сообщение провайдера**, **форму запроса без секретов** (секретов в ней нет), затем проверяет, что
запущенных Pod'ов нет, и **останавливается**. Ни второго Pod'а, ни второго тома он не создаёт — в коде
одного цикла просто нет.

При отказе вердикт будет: **GLOBAL VOLUME PUBLIC API ATTACHMENT = FAIL** (и это будет уже
наблюдавшийся отказ, а не предположение).

---

# §4. ЕСЛИ API ПРИМЕТ

Скрипт делает ровно то, что требует задание, и всё это в одном прогоне:

* печатает `Pod ID`, `datacenter`, фактические `mounts`, которые вернул провайдер;
* читает поток логов Pod'а (`GET /v2/pods/{id}/logs`) и ищет маркеры: том виден
  (`CANALLA_GV_*`), файл `global-volume-canalla-test.txt` создан (`CANALLA_GV_WRITE_OK`), содержимое
  прочитано обратно (`CANALLA_GV_DONE=<токен>`);
* завершает Pod через `POST /v2/pods/{id}/action` с `{"action": "terminate"}` — точное действие и
  точное тело взяты из живого контракта (`PodAction`: `start | stop | restart | terminate`);
* ждёт и проверяет, что **running pods = 0**.

---

# §5. КРОСС-ДЦ ПРОВЕРКА

`--cross-dc <ДРУГОЙ_ДЦ>`: второй дешёвый CPU Pod в другом датацентре, тот же ID тома, тот же тестовый
файл, сравнение содержимого. **Строго после** того, как первый Pod завершён: два Pod'а одновременно не
существуют ни в одном сценарии скрипта.

# ЧТО НУЖНО ОТ ВАС (одна строка)

**Скопируйте ID глобального тома из консоли** (Storage → ваш Global volume → поле ID; выглядит как
`gv_…`, UUID или подобное) и пришлите его. ID секретом не является, ключи не нужны.

Дальше без пауз и без вопросов:

```
python scripts/global-volume-attach-test.py --volume-id "<ваш ID>" --live --cross-dc US-KS-2
```

Результат будет ровно в формате §8 выше: `accepted: YES/NO`, HTTP статус и код провайдера при отказе,
mount/write/read, завершение Pod'а и `running pods = 0`, а при успехе — кросс-ДЦ сравнение содержимого.

Том уже создан, поэтому порядок такой: **первый** тест идёт в `US-TX-3` (тот же ДЦ, что у регионального
тома) — так вопрос «принимает ли API сам ID» остаётся изолированным от вопроса «монтируется ли он в
другом ДЦ»; **второй** тест — в другом ДЦ, и он же доказывает регион-независимость. Если хотите одним
прогоном сразу проверить мобильность, поменяйте порядок: `--datacenter US-KS-2 --cross-dc US-TX-3`.

# ЗАМЕЧАНИЕ ПРО БУДУЩУЮ АВТОМАТИЗАЦИЮ (важно для решения §6)

Даже при PASS публичного подключения останется вопрос: **как Canalla создаёт такой Pod
автоматически.** Вероятный ответ — тем же публичным `POST /v2/pods` с `mounts.network[0].volumeId =
<глобальный ID>`, то есть **изменение в коде сводится к одному значению**: политика уже умеет
`storage_type = global_volume` и уже **не** закрепляет датацентр (реализовано и покрыто тестами в
`1d02d84`). Если PASS подтвердится, план такой: перенос модели (`rsync`), проверка `mmap`/времени
загрузки, включение `storage_type`, живая генерация, кросс-ДЦ отказоустойчивость, и только потом
удаление регионального тома.
