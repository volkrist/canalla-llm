# Canalla LLM 1.2.1 — сценарий интерактивной Windows-приёмки

Статус: **подготовлен, НЕ выполнен.** Headless-зелёный CI не является GUI-приёмкой: пункты ниже
может закрыть только человек за живой Windows-машиной. Платные GPU для этой проверки не нужны.

## Что понадобится

* установленная **1.2.0** на Windows-машине с сохранёнными данными (чаты, файлы, память);
* тестовый установщик **1.2.1** из CI-артефакта `canalla-test-installer` (см. отчёт);
* **синтетические** данные и credentials. Production-секреты на машину не переносить;
* Defender **включён** — его не отключать.

## Перед установкой: зафиксировать базу

1. Запустить 1.2.0, убедиться, что приложение открывается и отвечает.
2. Записать: число чатов, наличие файла в File-search, размер `%LOCALAPPDATA%\Alex LLM\` и список
   верхнеуровневых папок. Это «до».
3. Сделать штатную резервную копию (Settings → Backup), если доступна, и запомнить её путь.

## Шаги приёмки

| # | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Установить 1.2.1 **поверх** 1.2.0 (обычный запуск setup.exe, не «/S») | Установка завершается, ярлык обновляется, второй копии продукта нет (`%LOCALAPPDATA%\Programs\Canalla LLM` одна) |
| 2 | Открыть приложение | Окно «Canalla LLM», версия в About = **1.2.1** |
| 3 | Проверить сохранность данных | Те же чаты/файлы/память, что «до»; `%LOCALAPPDATA%\Alex LLM\` не пуст и не пересоздан |
| 4 | Проверить sidecar | `/health` локального backend отвечает, продукт `alex-llm`, версия **1.2.1** (не 1.2.0!) |
| 5 | Computer (status chip) | Чип зелёный **Ready** после живого heartbeat, без кнопок и без автозапуска при входе в Windows |
| 6 | Tor (status chip) | Чип зелёный **Ready** только с сохранённым SOCKS5h-доказательством; не «configured» |
| 7 | Перезапуск приложения | Computer и Tor снова зелёные, **тот же** `device_id`, одно устройство (без повторного pairing) |
| 8 | Подключение к Gateway | «Подключить» активно (адрес `https://gateway.12testers.store` уже вшит), enrollment проходит |
| 9 | Статус AI | **AI Offline** до готовности модели — честно, без ложного Connected |
| 10 | Поиск GPU в двух регионах | При запросе модели Gateway ищет в **US-TX-3 и US-MO-1**; в статусе видно ожидание/поиск |
| 11 | Нет ложного Connected | Пока модель не готова — никакого зелёного «Connected»; зелёный только после реальной готовности |
| 12 | Stop / Cancel | «Остановить AI» останавливает compute; Cancel во время поиска запрещает запуск |
| 13 | Никаких самопроизвольных платных запусков | Пока пользователь не запросил модель, **новых Pod нет** (`GET /v2/pods` → пусто) |
| 14 | Пользовательские лимиты | `max_hourly_price` / session budget / idle-stop — те, что выставлены в UI, не переписаны |

## Проверки «нет ложного Connected» (жёстко)

* На шаге 9 при выключенном/неготовом compute статус обязан быть Offline/Connecting, а не Connected.
* Допустимо видеть amber «Connecting» только при живом поиске (окно 60 с).
* Если модель упала, чип обязан **перестать** быть зелёным (readiness TTL), а не «залипнуть».

## Чего в этой приёмке делать НЕ нужно

* запускать платный GPU ради самой Windows-проверки (шаги 10–12 проверяются UI/статусом; реальный
  ответ модели уже подтверждён отдельным GPU-тестом US-MO-1);
* менять production Gateway, `main`, теги или пользовательские лимиты;
* проверять «/S»-установку — это делает headless CI; здесь нужен именно интерактивный путь.

## Что считать результатом

Отчёт с «до/после» по данным, скриншотами чипов Computer/Tor/AI и вывода `/health` установленного
sidecar. Любой красный пункт — блокер публикации 1.2.1, а не «шум».
