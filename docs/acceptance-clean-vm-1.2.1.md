# Canalla LLM 1.2.1 — приёмка на чистой Windows 11 VM (план)

Дата: 14.10.2026. **VM не создана** (см. «Кто что делает»). Платные облачные ресурсы не заказаны.

## Зачем

На рабочей машине Windows Defender снимает **наши собственные** неподписанные бинарники
(`Trojan:Win32/LummaStealer.DO!MTB`), поэтому GUI-приёмка там невозможна. Нужна чистая,
изолированная Windows, где проверка идёт «с нуля» и результат не зависит от истории этой машины.

## Где (по предпочтению)

1. **Изолированная VM на доверенном хосте** (Hyper-V / VirtualBox / VMware на машине без этой
   истории детекций) — предпочтительно.
2. **Облачная VM** (Azure/AWS/GCP) — **только с согласованием стоимости**; я ничего не заказываю.
3. Не использовать потенциально заражённый рабочий компьютер как хост и не давать VM к нему сетевой
   или файловый доступ.

## Настройка VM (до установки)

* Чистая **Windows 11**, все обновления, **Defender обновлён** (не отключать!).
* **Снимок (snapshot) сразу после настройки** — чтобы повторять приёмку с чистого состояния.
* **Никаких production API keys**, никаких личных паролей, никаких общих папок, буфера обмена и
  проброса дисков с рабочей машины. Сеть — по возможности изолированная.
* Всё, что вводится (activation code, RunPod key) — **синтетическое/тестовое**.

## Получить установщик из доверенного артефакта

Скачивать **напрямую** из GitHub Actions (не копировать с рабочей машины):

```bash
gh run download 38476189049 -R volkrist/canalla-llm -n canalla-test-installer -D ./installer121
sha256sum "./installer121/Canalla LLM_1.2.1_x64-setup.exe"
```

Ожидаемый SHA256 — **`24bc0a28e4b7f7252407be5aafcde239dfd02d7e7940d411bb35963f03fe8c29`**
(размер 91 928 775 Б, `ProductVersion=1.2.1`). Несовпадение — **стоп**.

Для проверки обновления поверх 1.2.0 нужен также **1.2.0** установщик (любой проверенный:
`sha256 61a99cfc…` или `2a6383ca…`).

## Правило остановки

**Если Defender блокирует файл и на чистой VM — не отключать защиту, не добавлять исключений,
остановить установку и разбираться.** Это будет означать, что дело не в истории рабочей машины, и
приёмку продолжать нельзя до реакции Microsoft
(`docs/defender-false-positive-investigation.md`).

## Порядок приёмки (14 пунктов)

Порядок важен: **сначала данные, потом обновление**.

1. Снять **snapshot «чисто»**.
2. Установить **1.2.0**, дать приложению запуститься.
3. Создать **тестовые данные**: пара чатов, файл для File-search, заметка в память; зафиксировать
   «до» (число чатов, размер `%LOCALAPPDATA%\Alex LLM\`, скриншот).
4. Снять **snapshot «1.2.0 с данными»** — точка возврата.
5. Установить **1.2.1 поверх** → пункт 1 сценария.
6. Запуск без ошибок → п.2; версия в UI и `/health` sidecar = **1.2.1** → п.3.
7. **Данные сохранены** (те же чаты/файлы/память) → п.4.
8. Computer **always-ready** без кнопок и без автозапуска при входе в Windows → п.5.
9. Tor **always-ready** с реальным SOCKS5h-доказательством → п.6.
10. Перезапуск приложения: Computer и Tor снова зелёные, **тот же** `device_id` → п.7.
11. Gateway: «Подключить» активно, адрес вшит, enrollment проходит → п.8.
12. **AI Offline** до готовности модели; зелёный Connected **только** при реально готовой модели →
    п.9, п.11. amber «Connecting» допустим только при живом поиске (окно 60 с).
13. **Два региона**: при запросе модели Gateway ищет в US-TX-3 **и** US-MO-1 → п.10.
14. `max_hourly_price` / session budget / idle-stop — те, что выставлены в UI → п.11.
15. **Stop / Cancel**: остановка работает, Cancel во время поиска запрещает запуск → п.12.
16. Никаких самопроизвольных платных Pod: `GET /v2/pods` → пусто → часть п.13.
17. UI без критических ошибок → п.13.
18. **Перезагрузка Windows**: Computer и Tor снова готовы автоматически → п.14.
19. Снять финальный snapshot и собрать отчёт со скриншотами.

Платные GPU/CPU Pod для этой приёмки **не нужны**; реальный ответ модели уже подтверждён отдельным
GPU-тестом US-MO-1 (`docs/report-2026-10-13-gpu-acceptance-us-mo-1.md`).
