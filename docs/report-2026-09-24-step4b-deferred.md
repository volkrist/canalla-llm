## 3. Почему это ограничение среды, а не дефект кода

Приёмка не провалилась — её **не стали доводить до конца**, и это осознанное решение. Чтобы оно не
выглядело как отговорка, зафиксируем измеренное: десктопная VM на этой машине была **технически
выполнима**.

| Факт | Значение |
|---|---|
| VirtualBox | **7.2.8** установлен, `VBoxManage` отвечает |
| Аппаратная виртуализация | поддерживается (вложенная — нет) |
| Проверка боем | существующая VM была запущена headless, кадр снят (`screenshotpng`), VM выключена |
| Головной GUI-инструментарий | `screenshotpng`, `keyboardputstring`, `keyboardputscancode` — доступны, то есть живой десктоп можно было бы вести и фиксировать без окна |
| Сеть и загрузка | `releases.ubuntu.com` — HTTP 200, скорость 4,3 МБ/с (100 МБ за 24 с) |
| Свободное место | `D:` — 85 ГБ |
| RAM хоста | **7,9 ГБ всего** |

То есть блокером был не инструментарий, а цена: ~6,2 ГБ загрузки, ~40 ГБ диска и почти вся память
машины на несколько часов ради одной приёмки. Запускать это на рабочем ПК разработчика — решение,
которое владелец продукта отклонил, и это зафиксировано как ограничение среды.

**Исправление предыдущего вывода.** В отчёте STEP 4A (и в `linux-ubuntu.md` §6 на тот момент) было
сказано, что VirtualBox отсутствует. Это **неверно**: VirtualBox на машине установлен, и VM-путь
существовал. Ошибка была в проверке, а не в решении: к моменту STEP 4B решение всё равно изменилось
сознательно, по причине нагрузки на рабочую машину. Соответствующая строка отчёта STEP 4A помечена
исправлением.

## 4. Изменение scope релиза 1.2.0

| Цель | Статус в 1.2.0 | Следствие |
|---|---|---|
| **Windows x86_64** | **PRODUCTION** | цель релиза; все Windows-гейты обязательны |
| **Ubuntu 24.04 LTS x86_64** | **PREVIEW / EXPERIMENTAL** | не сертифицирован: артефакт не публикуется, Linux-манифест обновлений не публикуется, автоматическое обновление Linux не заявляется как production |

Публичного Linux-артефакта в 1.2.0 **нет намеренно**: предложить пользователю пакет — значит принять
обещание поддержки, которое этот релиз не может подкрепить. Код Linux при этом сохраняется, собирается
и тестируется — он просто пока не распространяется.

**Чего это решение не меняет.** Linux не объявлен неподдерживаемым: его гейты по-прежнему проходят и
остаются в наборе. Дефект **общего** кода, который вскрывает Linux-гейт, остаётся блокером релиза
Windows 1.2.0, потому что Windows исполняет те же платформенно-нейтральные пути. Блокером перестала
быть только сама отсутствующая десктопная приёмка.

## 5. Что меняется для финального этапа

Из списка обязательных гейтов **удаляется один**: локальная Ubuntu Desktop VM больше не блокирует
Windows-релиз 1.2.0. Windows-гейты остаются ровно теми же и обязательными: чистая Windows-среда,
self-contained установка, реальный login/autostart, Computer Ready, bundled Tor Ready, восстановление
после падений, корректность AI Connected/Disconnected, updater, production-подпись, апгрейд 1.1 → 1.2
с сохранением данных, естественно-языковой Tor-маршрут, финальные хеши, маршрут Gateway, production
Windows-манифест, merge и tag.
